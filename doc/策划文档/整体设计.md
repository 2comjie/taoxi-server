# 一、产品定位

**多人在线国风田园经营手游**

玩家回到一座逐渐荒废的山村，通过种植、加工、经营、建设和村民交往恢复村庄；既拥有私人家园，也能前往共享小镇，与其他玩家互动及参加合作活动。

基本体验：

- 平台：iOS、Android
- 客户端：Unity
- 服务端：Go
- 单次游戏：5～15分钟
- 核心模式：单人经营
- 社交模式：异步拜访 + 共享大厅 + 轻量合作
- 节奏：低压力、放置生产、长期收集
- 商业化：装饰、外观、月卡、通行证为主

# 二、三层核心循环

## 1. 分钟循环

```text
收获作物
→ 补充生产队列
→ 完成订单
→ 获得金币与经验
→ 建造或升级
```

解决玩家每次上线“做什么”。

## 2. 每日循环

```text
每日任务
→ NPC委托
→ 好友互助
→ 大厅活动
→ 限时订单
→ 获得日常资源
```

解决每日回流和社交参与。

## 3. 长期循环

```text
提升等级
→ 扩建土地
→ 解锁生产链
→ 修复村庄
→ 推进剧情
→ 收集角色、装饰和图鉴
→ 进入新区域
```

解决长期目标。

# 四、核心资源系统

## 1. 货币

首版控制在四种以内：

| 货币 | 主要来源 | 主要消耗 |
|---|---|---|
| 铜钱 | 订单、任务、出售产品 | 建筑、种子、普通装饰 |
| 建材 | 采集、任务、合作订单 | 建造、升级、扩地 |
| 玉石 | 成就、活动、少量付费 | 稀有装饰、加速 |
| 灵玉 | 付费 | 外观、通行证、礼包 |

不要为每个玩法设计独立货币，否则玩家认知压力过大。

## 2. 道具类型

- 种子
- 农作物
- 基础材料
- 加工产品
- 料理
- 建筑材料
- 装饰
- 礼物
- 活动道具
- 消耗道具
- 剧情物品

所有资源变化必须形成服务端流水：

```text
玩家 + 资源类型 + 变化数量
+ 变化前数量 + 变化后数量
+ 来源系统 + 业务流水号 + 时间
```

# 五、生产经营系统

## 1. 种植

农田状态：

```text
空闲 → 已播种 → 生长中 → 已成熟 → 收获 → 空闲
```

主要参数：

- 作物解锁等级
- 种子价格
- 生长时间
- 基础产量
- 仓库售价
- 加工用途
- 季节标签
- 经验奖励

天气和季节首版只影响表现，不影响产量，避免玩家错过时间而受罚。

## 2. 养殖

建议第二阶段加入：

- 鸡：鸡蛋
- 牛：牛奶
- 羊：羊毛
- 蜜蜂：蜂蜜

养殖不设计死亡和疾病，仅包含投喂、等待和收获。

## 3. 加工生产

生产链示例：

```text
水稻 → 大米 → 米糕
小麦 → 面粉 → 馒头
黄豆 → 豆腐 → 豆腐料理
牛奶 → 奶酪 → 甜品
桃子 → 桃酱 → 桃花糕
```

每个生产建筑包含：

- 解锁条件
- 建造成本
- 配方
- 生产时长
- 队列数量
- 建筑等级
- 助手加成

## 4. 仓库

仓库负责限制资源囤积，但不能过度打断玩家：

- 作物和产品占容量
- 装饰、任务物品不占容量
- 满仓时允许收取关键任务奖励
- 支持分类、筛选和来源跳转
- 扩容主要消耗游戏内材料

# 六、订单经营系统

订单是经济系统的主要资源出口。

订单类型：

- 普通订单
- NPC订单
- 剧情订单
- 限时订单
- 合作订单
- 活动订单
- 求助订单

订单生成需要考虑：

- 玩家已解锁物品
- 当前生产能力
- 库存情况
- 最近订单记录
- 商品生产时长
- 玩家等级
- 当日完成数量

奖励公式可以抽象为：

```text
奖励价值 =
物品基础价值
× 数量
× 生产耗时系数
× 订单品质系数
× 难度修正
```

不允许随机生成玩家尚未解锁或短期内无法生产的商品。

# 七、建造与家园系统

## 1. 建筑分类

- 生产建筑
- 功能建筑
- 住宅
- 景观建筑
- 道路和地表
- 树木花草
- 水景
- 互动家具
- 活动限定建筑

## 2. 编辑能力

- 网格摆放
- 移动、旋转
- 碰撞检查
- 批量移动
- 一键收纳
- 撤销修改
- 布局方案
- 区域主题
- 家园预览和分享

## 3. 繁荣度

繁荣度用于衡量家园建设进度：

- 建造新建筑
- 升级功能建筑
- 摆放首次获得的装饰
- 完成区域建设目标
- 收集主题套装

同一装饰重复摆放不应无限增加繁荣度。

# 八、成长系统

成长维度分为：

| 成长线 | 作用 |
|---|---|
| 玩家等级 | 解锁作物、建筑、系统 |
| 家园繁荣度 | 解锁土地和区域 |
| 建筑等级 | 提高队列、效率和产量 |
| NPC好感度 | 解锁故事、礼物、服装 |
| 乡社等级 | 解锁多人公共设施 |
| 图鉴进度 | 提供长期收集奖励 |

首版重点只做玩家等级、繁荣度和建筑等级。

# 九、任务与剧情系统

## 1. 任务类型

- 新手引导
- 主线任务
- 支线任务
- NPC委托
- 日常任务
- 周常任务
- 成就
- 活动任务

## 2. 通用任务条件

- 获得物品
- 消耗物品
- 收获作物
- 制作产品
- 完成订单
- 建造或升级
- 与NPC对话
- 达到等级
- 拜访好友
- 参加多人活动
- 到达指定位置
- 播放指定剧情

## 3. 剧情系统

支持：

- 对话
- 角色立绘或场景角色
- 镜头控制
- 表情和动作
- 音效
- 场景物件变化
- 玩家选项
- 条件分支
- 剧情回顾
- 跳过和自动播放

分支主要影响对话、好感和奖励，不建议首版形成复杂永久世界线。

# 十、NPC与助手系统

## NPC

每个重要NPC包含：

- 基础资料
- 出现时间与地点
- 好感等级
- 喜好物品
- 日常委托
- 个人剧情
- 特殊商店
- 家园访客行为

## 助手角色

助手可以参与生产，但不要形成复杂战斗养成：

- 分配至生产建筑
- 提供生产速度或产量加成
- 拥有一个被动技能
- 解锁角色故事
- 更换服装和动作
- 在家园中自主活动

角色获取建议以剧情、活动和收集为主，避免成为强数值抽卡核心。

# 十一、探索与休闲玩法

## 区域探索

每个区域包含：

- 主线故事
- 采集点
- NPC
- 宝箱
- 环境谜题
- 特殊材料
- 图鉴内容
- 区域修复目标

探索体力只限制额外奖励，不阻止剧情推进。

## 小游戏

优先选择能复用经营资源的玩法：

- 钓鱼
- 合作烹饪
- 赶集订单
- 放花灯
- 拼图
- 寻物
- 采茶
- 节奏演奏

首发最多做两个，避免内容过度分散。

# 十二、多人系统

## 1. 私人家园

- 玩家自己的经营主场景
- 最多邀请3名好友实时进入
- 允许互动、拍照、有限帮助
- 禁止访客修改布局或取走资源

## 2. 异步拜访

主人离线时，好友访问家园快照：

- 点赞
- 留言
- 帮忙
- 查看装饰来源
- 拍照
- 关注家园

## 3. 共享小镇大厅

- 每条分线20～30人
- 玩家位置和外观同步
- NPC、公共商店、茶馆、集市
- 表情、动作、合照
- 组队和活动入口
- 节日公共场景

## 4. 多人合作房间

- 2～4人
- 单局3～8分钟
- 自动匹配或好友组队
- 合作烹饪、赶集、钓鱼等
- 服务端统一结算
- 支持断线重连和奖励补发

## 5. 乡社

- 20～30名成员
- 社内聊天
- 每日互助
- 每周合作订单
- 公共建筑
- 贡献和乡社商店
- 成员家园展示

## 6. 有限交易

不做自由交易，使用以下方式：

- 限价摆摊
- 每日次数限制
- 普通商品才能出售
- 系统手续费
- 求助订单
- 禁止付费物品和稀有资源转移

# 十三、日常与活动系统

## 日常结构

每日控制在20～30分钟内完成：

- 收获3次
- 完成5个订单
- 制作3种产品
- 与NPC交谈
- 帮助好友1次
- 参加大厅活动1次

日常任务可以累计活跃度，不强制完成全部项目。

## 活动框架

支持：

- 签到
- 活动任务
- 活动订单
- 活动生产建筑
- 活动商店
- 剧情章节
- 限时地图
- 合作进度
- 通行证
- 排名展示

治愈游戏的排名奖励差距应当较小，主要奖励来自个人和全服进度。

# 十四、商业化设计

适合出售：

- 建筑皮肤
- 家园装饰
- 角色服装
- 宠物外观
- 表情动作
- 月卡
- 赛季通行证
- 资源礼包
- 合理的生产加速

不建议：

- 强制观看广告
- 付费独占关键生产建筑
- 严重卡仓库容量
- 付费角色提供巨大产量优势
- 高频弹窗礼包
- 依赖排行榜逼迫付费

# 十六、Unity客户端结构

建议按业务模块组织：

```text
Core
├─ 启动流程
├─ 时间
├─ 网络
├─ 配置
├─ 资源加载
└─ 事件系统

Gameplay
├─ Farm
├─ Production
├─ Inventory
├─ Order
├─ Building
├─ Quest
├─ Story
├─ NPC
└─ Social

Presentation
├─ UI
├─ Character
├─ Environment
├─ Audio
└─ Effects
```

生产、订单、任务等逻辑不要直接写在UI组件里。

# 十七、Go服务端结构

早期建议采用**模块化单体**，不要一开始拆成大量微服务：

```text
Go Server
├─ Gateway
├─ Account
├─ Player
├─ Inventory
├─ Farm
├─ Production
├─ Building
├─ Order
├─ Quest
├─ Story
├─ Friend
├─ Lobby
├─ Match
├─ Room
├─ Payment
└─ Admin
```

基础设施建议：

- PostgreSQL或MySQL：永久数据
- Redis：登录状态、缓存、匹配、大厅在线状态
- WebSocket：大厅及房间实时通信
- HTTP：普通业务请求
- 对象存储：家园分享图、运营资源
- 消息队列：后期用于邮件、日志、活动结算

所有物品、货币、订单奖励由Go服务端权威计算。
